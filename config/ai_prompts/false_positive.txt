## Analysis Guidelines

Consider the following when determining if this is a false positive:

1. **Evidence Quality**
   - Is the evidence conclusive or circumstantial?
   - Could the detection be triggered by benign behavior?
   - Are there multiple indicators or just one?

2. **Technology Context**
   - Does the vulnerability make sense for this technology stack?
   - Are there known false positive patterns for this scanner/template?
   - Is the version/configuration actually vulnerable?

3. **Response Analysis**
   - Does the response truly indicate vulnerability?
   - Could the matched pattern be legitimate application behavior?
   - Are error messages/behaviors consistent with exploitation?

4. **Common False Positive Patterns**
   - Generic error messages that aren't exploitable
   - Security headers that are intentionally configured differently
   - Version disclosure without actual vulnerability
   - WAF/IDS false triggers
   - Development/staging indicators in production
